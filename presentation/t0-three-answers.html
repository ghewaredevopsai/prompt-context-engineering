The phenomenon

One request goes in. Four things you did not type go with it.

Only the top pipe is out of your hands. The other three are files you can write, a conversation you can restart, and a set of attachments you can choose. This module is about those three.

The three answers on the right are not exaggerated: they are the three shapes you get from the same one-line request against a repository that has never been told how the team works. The one that invents a pricing rule is the dangerous one, because it looks like the other two.

Where the leverage is

The part you type is the smallest part of what you send

1What you type

Tens of tokens. Rewritten every time. The part everyone tries to improve first, and the part with the least room in it.

2What you attach

Thousands of tokens, chosen per request. Attach the folder and you have made a decision about cost and accuracy without noticing you made one.

3What stands

Written once, sent on every request forever. The rules a new hire would otherwise learn by having a pull request rejected.

The order people work on these is backwards. Most teams spend a month collecting clever phrasings for box 1 and never write box 3, which is the one that changes every answer the team gets, every day, without anyone retyping anything.
Lab 0 now: clone the freight desk, run its tests, and measure what "just attach the repository" actually costs. Five minutes. Everything after this is measured against the number you write down.

Keep the three boxes in this order for the rest of the module: the tiers work up from what you type to what stands. Tier 1 is box 1, Tier 4 is box 2, and the instruction files that make up box 3 belong to the Copilot-as-Assistant module, which this one deliberately does not repeat.
